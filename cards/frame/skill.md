### 分组框（frame）

把几张卡圈进一个框，**整体拖动**、可折叠。板大了之后用它分区：一块地是一摊事。

```json
{"type":"frame","title":"第三季度要交的东西","x":40,"y":40,"w":720,"h":460}
```

- 框的**标题就是 `title`**（没有 `frame.title` 这种字段）；框的**大小就是 `w/h`**——框多大就圈多大。
- `frame.collapsed`（默认 false）：折叠后画布上只剩这个框和一个计数，框里的卡**一张都没删**，只是不画。
- **谁在框里**记在**子卡**身上：给子卡打 `{"frameId":"<框的卡片 id>"}`，取消归属传 `{"frameId":null}`。
  框里不存成员名单——存了就要跟「卡被删了 / 被拖出去了」两头对齐，那是又一处会腐坏的一致性。
- `frameId` 必须指向**同一块板上**一张 `type=frame` 的卡片，否则 400；框被删掉时**子卡不删**，
  只是它们的 `frameId` 被清空（框是组织手段，不是容器所有权）。
- 摆位：把子卡放进框的**几何范围**里（它们的坐标仍是画布绝对坐标，不是相对框的）。
  浏览器里把卡拖进框会自动归属，你走 API 的话自己算一下落点就行。
- ⚠️ **摆进去 ≠ 归属**：只写坐标不写 `frameId`，框上仍然是「0 张卡片」，阅读模式里也是个空框。
  批量建卡 / 整板改写之后**自己补一遍 `frameId`**——服务端不会按几何替你认领
  （用户在界面上可以点框上那颗「收纳 N 张」显式收一次，但那是**人**的决定，没有对应的 API 动作）。

**跟子画板卡（board）的分界线**——两者不是一回事，别混着用：

| | `frame` 分组框 | `board` 子画板卡 |
| --- | --- | --- |
| 数据 | 还在本板上（只多一个 `frameId`） | 在**另一块板**里 |
| 打开 | 就在眼前，折叠只是收起来 | 双击**下钻**进另一块板 |
| 适合 | 「这一摊归一起，一起搬」 | 「这一摊挪出视线，要看再进去」 |
| 连线 | 框里的卡照常跟框外的卡连线 | 跨板不连线 |

**坑**：

1. `frame` 包默认**不启用**（大板才用得上）。新建 400 时先 `GET /api/card-packs` 看开关。
2. **信封不收 frame**（`envelope: false`）：`frameId` 是本板内主键，换台机器指不到东西——
   同 image/pdf 的 `file.uploadId`、board 卡的 `boardRef.boardId`。要在另一台机器上重建分组，
   先在那边建框拿到新 id，再逐张 `PATCH {"frameId": "<新 id>"}`。
3. **整理会绕开框**：`POST /tidy` 的十一种模式一律**跳过分组框本身与被它圈住的卡**，
   只重排自由卡。框是你手工圈出来的组织意图，重排会把它拆散——想让框里的卡重新摆，
   先把它们拖出框，或者直接给坐标（`PUT /state`）。

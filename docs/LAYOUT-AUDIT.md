# 整理算法与可撤回操作审查

## 验收目标

这次审查覆盖全部 11 种模式。正确性不是“能返回坐标”：卡片不能丢失或重叠，内容与连线保持完整，分组框不移动也不被新布局覆盖，业务分类使用有效字段，DAG 的上下游方向正确，重复整理稳定；每次真实整理必须可以独立撤销、重做。

乱板的建议顺序是：网格先获得整洁全景；按类型分区快速分类；有明确先后关系再用流程或分层；原有结构仍有价值时用整齐化。不同模式优化不同目标，流程布局强调方向，不承诺像网格一样紧凑。环图保留返回边，不可能让环上每条边都向前。

## 模式审查结论

| 模式 | 主要修复或核验 |
| --- | --- |
| tidy 整齐化 | 聚类不再连锁吞列；交叉重排不来回翻转；中心基准贯穿收尾，重复整理不漂移；异形卡消重叠 |
| flow 流程 | 分支和汇合点位于全部前驱之后；环回边单独处理；重复边、自环、坏边、长环不破坏算法 |
| LR / TB 分层 | DAG 方向、异形卡间距与孤卡区域；重复边取最强权重并稳定排序，输入顺序不能覆盖关系强度 |
| group 类型分区 | 量化后再推进游标，保住行间、卡间、组间最小留白 |
| grid 网格 | 统一单元步长；根据卡数与尺寸选择约16:10的均衡布局，18张异形卡由2×9改为4×5 |
| timeline 时间线 | UTC自然日、有效日期范围与历史业务日期；不依赖浏览器或服务器本地时区 |
| kanban 看板 | 枚举真实值优先于显示标签；同列顺序确定；未知状态不被误判成已开工 |
| matrix 四象限 | 缺失/空值不转成0；中位数不溢出；只从有效双维规格中选口径；不适用的卡进入未归类 |
| swimlane 泳道 | 类型×状态二维分格；混合尺寸无重叠、顺序稳定、不受排除的框内卡影响 |

全局入口还修复了固定框避障、孤儿frameId永久跳过、超界坐标被截断的风险。必要时整体平移自由区域，保持内部结构；没有安全空间时原子拒绝。显式未知mode返回400；异步计算期间出现其他编辑返回409。无变化不追加空历史，`changed`报告真实移动数量，`moved`保留旧的参与计算数量口径。

## 真实 API 实验

`node scripts/audit-layouts.mjs` 只有带 `--write` 才创建专用测试板。实验包含一个总览与11个子板，每板同样的18张异形自由卡、固定框和框内卡，混合任务、指标、待办、文本及分支汇合、独立子图和孤卡。

修复前，10种模式把自由卡排入固定区；tidy重复整理仍移动，flow有两条DAG边倒流。修复后，真实HTTP API逐一整理两次：11种模式均无自由卡重叠、无固定区覆盖、固定卡不动、内容/连线保留、重复稳定，flow/LR/TB的DAG倒流数为0。

浏览器检查了实际画板。浮动工具条会避让顶部工具箱；适应视野也保留工具箱空间，避免“坐标正确但第一行看不见”。专用画板属于运行数据，不加入公开源码；复现脚本与回归测试随源码交付。

## 连续历史与快捷键

逐步编辑历史采用字段差量，每板100步/8MiB。同卡同字段2秒内合并；整理和拖动独立记步；纯视口不记录。游标随文件保存，刷新后继续撤销/重做，新编辑截断redo。整板checkpoint仍是另一层灾备。

Ctrl/Cmd+Z撤销，Ctrl/Cmd+Shift+Z重做，Windows/Linux也可Ctrl+Y。撤销先等待当前写操作处理完成，再保存待提交几何并使用严格版本校验；快速Delete→CtrlZ不需要重按。旧提示条同样走持续历史，用内容签名防止撤销后来的修改，自动适应视野不会误使提示条失效。

输入、contenteditable、IME、弹窗和iframe保留自己的键盘/粘贴操作；历史抽屉只允许撤销/重做组合键越过非编辑控件门禁。Space临时平移只有一个监听来源，松开或失焦立即释放。左下角问号可打开完整快捷键帮助。

恢复删除保留卡片ID、连线、评论与未知字段；恢复父级会形成循环时拒绝。任务关联或已执行任务状态变化会停止旧撤销链：撤销只恢复画板，不取消已执行的外部任务。历史保存失败不让主写入假失败，界面会说明记录不可用。

## 自动化与边界

固定种子与对抗测试覆盖异形尺寸、密集重叠、阶梯布局、分支汇合、强弱重复边、坏边、长环、缺失字段、1000张大卡、坐标边界和固定障碍。真实浏览器测试覆盖连续整理undo/redo、刷新、延迟网络响应、浮动工具条实际命中与窗口缩放。

最终门禁采用 `npm run check`，包括仓库检查、脚本单测、TypeScript、生产构建、完整API smoke和全部Playwright测试。测试写入均使用隔离数据，真实服务只在专用实验板上验证整理。项目仍遵循单进程写数据和受信任网络的部署边界，详见 [部署指南](DEPLOYMENT.md)。

本轮最终验收结果：`npm run check` 全绿，12项脚本单测与210项Playwright测试通过；完整API smoke、类型检查、生产构建和源码门禁均通过。专用HTTP实验的11种模式全部通过，网格在18张异形卡案例中为4列×5行。

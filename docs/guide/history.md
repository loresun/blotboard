顶栏「历史」默认打开**连续撤销**。可以先试网格，再试分层、看板；不满意时逐步撤销，或重做回来，不用在一次性提示条消失前抢着点击。

## 连续撤销与重做

- 撤销：`Ctrl+Z` / `⌘Z`，或历史里的「撤销上一步」。
- 重做：`Ctrl+Shift+Z` / `⌘Shift+Z` / `Ctrl+Y`，或「重做下一步」。
- 编辑输入框时，快捷键交给文字编辑器；回到画布后才操作整板历史。
- 历史按画板保存在服务端，刷新页面或重新启动后仍能继续。其他窗口和 Agent 经 API 提交的改动也会记入。
- 新修改会截断尚未重做的分支。撤销 / 重做本身只移动游标，不新添反向记录。

编辑、增删卡片 / 连线 / 评论、拖动与整理都会记录。每次整理是独立一步，纯平移、缩放视口和轮询不算编辑。同一张卡相同字段的连续保存，在 2 秒内合并成一步；不会每按一个键保存一份整板。

刚拖完立即撤销时，画板会先等几何变化保存完成，再撤销它，避免延迟保存把撤销结果冲掉。若其他窗口或 Agent 已经改动了新版本，本次撤销会停止并同步最新画板；看清新内容后再决定。

## 记录范围与限制

每板保留最近 **100 步或 8 MiB**，以先到的上限为准。历史只保存变化的字段及增删对象；普通单卡编辑不复制整板。超出容量的单次改动可能没有逐步撤销记录，界面会说明，此时可检查历史快照。

**撤销只恢复画板内容，不取消外部任务、不撤回已发送消息，也不删除上传文件。** 任务关联或执行状态改变时，会停止旧撤销链并明确提示，避免把真实运行的任务伪装成「已撤销」。之后的普通画板编辑建立新的历史。删除任务卡后撤销，可恢复原卡及其引用；这不会重新执行任务。

历史文件位于数据目录的 `history/`。手工绕过 API 改板或历史文件损坏，会使旧撤销链停止，以免覆盖历史之外的内容。历史写入失败不阻断已经成功的画板保存，但页面会提示撤销记录不可用。删除整块画板会清理其逐步历史；恢复删板请使用快照或备份。

## 工作日志与整板快照

「改动记录」展示批量操作的来源和摘要；「历史快照」是在整板改写、信封落板、粘贴、服务端整理、批量改删和插入模板**之前**保留的整板备份。它们独立于连续撤销。

快照回滚需要确认，会覆盖卡片、连线与评论；回滚前还会再保存一份快照。单卡编辑和普通拖动使用轻量历史，不生成整板快照。画板删除后快照按保留策略继续存在，供恢复误删的整板使用。

## 给 Agent 的接口

先 `GET /api/boards/{id}` 取得最新 `updatedAt`，再 `GET /api/boards/{id}/history` 查看 `canUndo`、`canRedo` 与步骤摘要。执行时 `POST /api/boards/{id}/history`，请求体为 `{"action":"undo"}` 或 `{"action":"redo"}`，同时带写入鉴权和 `x-board-since: <updatedAt>`。

版本不一致返回 409，当前画板不变。成功响应带新画板与历史状态，操作后应回读验证。不要循环吞掉 409 自动重试，否则可能撤销用户刚提交的新操作。

任务功能**永远可用**：没接任何外部执行方时，画板自带一个 local 后端，Issue 落在本地、并给你生成一段完整的 prompt。

## 一张任务卡的四个状态

| 状态 | 意思 |
| --- | --- |
| **想法**（idea） | 刚写下来，还没决定做 |
| **已建 Issue**（issued） | 转成 Issue 了，等着开工 |
| **执行中**（running） | 已经派出去了，进展在回写 |
| **完成**（done） | 收工 |

## 走一遍

1. 建一张**任务卡**，把「要什么」写清楚（标题 + 正文，正文就是给执行方的说明）
2. 卡片上「**转 Issue**」——同时会把**连着它的那些卡片**的内容一起注入 Issue 的上下文。这一步很关键：任务不该孤零零一句话，它周围的背景卡片就是它的上下文
3. 「**发起**」——
   - 接了外部执行方：直接派单，`sessionId` 回到卡上，进展开始回写
   - 内置 local 后端：生成一段完整的 prompt，任务抽屉里一键复制，粘给你手边任何一个 agent
4. 进展、产出、结论回到**同一张卡**

## 任务台（顶栏左上角的站点导航里）

跨画板管理全部 Issue 与执行任务：待派 / 进行中 / 等我处理，一页看全。从画板过去时会预过滤到当前这块板。

任务台还管三件画布上管不了的事：

- **Runner 设置** —— 注册本机的 coding agent、选默认 agent、定权限档位
- **权限请求** —— agent 执行中要动某个文件 / 跑某条命令时，在这里点同意或拒绝
- **孤儿 Issue** —— 卡片被删了但 Issue 还在的那些，在这里能看到

## 接哪种执行方

三选一，按优先级：

1. **通用 http 后端** —— 任何按 `docs/RUNNER.md` 协议实现的服务
2. **ACP agent** —— 本机的 coding agent，画板直接 spawn 它的子进程，流式 transcript / 权限确认 / 中止都回到任务台
3. **local**（都不配时的默认） —— Issue 存本地，「发起」= 生成 prompt

第三种最省事也最稳：没有任何外部依赖，你手边任何一个 agent 都能接着干。

## 一条边界

接了外部执行方时，**任务的真源在那边**，画板只存引用 ID，不复制业务状态。所以任务台上看到的状态永远是那边的实况，不会出现「画板说做完了、执行方说还在跑」这种分裂。

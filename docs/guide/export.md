顶栏「**导出**」。菜单从上往下就是按「多数人要哪个」排的。

## 导出 PDF（头两项）

分页、纸张、页边距、页码与目录都由画板自己排好，再交给系统打印（对话框里选「另存为 PDF」）。产物是矢量文字：**链接可点、文字能选能搜**，图片按原图嵌进去，卡片不跨页。

「导出 PDF」用上次的设置直接出；「PDF 排版设置…」打开带**真实分页预览**的面板——纸张、字号、分栏改一下，页数当场变。整页说明见 [导出 PDF](/docs?doc=pdf)。

## 排版导出 · HTML

版式在服务端算好，给你一份**自包含的单文件 HTML**：

- 零外链，离线双击就能开
- 直接打印就是 A4 的 PDF
- 规格卡按规格出属性表，图表在服务端渲成矢量图
- 换台机器打开还是这个样子

离线可开、随手转发的首选；要能印、要页码与目录用上面的 PDF。菜单里还有两个变体：**先预览一下**（同一份产物，不下载，新标签打开）和**带评论的评审版**（把未解决的批注一并印出来，适合走评审）。

画布上开着筛选时，菜单里会多一项「**只导筛选命中的**」——口径和你在画布上看到的完全一致。

## PNG

整块板的截图。导出前会把屏幕外的卡片也画出来再截，所以不会缺角。

## Markdown

给人读、也给模型读。卡片按阅读顺序摊开，连线的关系 / 强弱 / 标签一并写出来。想把一块板喂给某个 agent 当上下文，这个格式最省事。

## JSON

整块板的原始结构，**可以原样改回来**（画板配置里粘回去就是）。备份、迁移、当模板复用都走它。

## 画板包（能带走，也能带回来）

前面五种是**产物**；这一种是**搬家用的**——一整块板（名字、分组、卡片、连线、评论、
图片与附件）打成一个 `.blotboard.json`，在另一台画板上导进去就是原来的样子。

- 顶栏「导出 → 导出画板包」是当前这块板；左栏右键一块板 / 一个分组，也能导那一批；
  存储面板里的「备份整个画板库」是全部。
- **子画板跟着走**：板上有子画板卡的话，它指的那块板会一起打包——不然对端点开那张卡是死链。
- 图片和 PDF 的**字节**在包里（总量 24 MB 封顶，超了会在导入时说明哪几个没跟过来）。

### 库很大的时候：分卷

一份包最多装 **200 块画板**。超过这个数就**分卷**：备份会一次下载好几个文件，
文件名带着「第几卷 / 共几卷」，每一卷都是一份**完整可导入**的画板包。

要点只有一条：**几卷就得留几个文件**。少存一个文件就是少一批板，
而恢复的时候逐卷导入就行，顺序不重要。跨卷的子画板引用要等它所在那卷也导进来才连得上。

调接口的话：`GET /api/boards/export?…&plan=1` 先看这次要几卷（不真的打包），
再逐个 `&volume=1`、`&volume=2`… 取。不给 `volume` 直接要一批超限的板会**当场报错**
并把整个分卷计划附给你——不会给你一份「看着成功」的残包。

## 导入画板

左栏「新建」旁边的箭头 → **导入画板…**，或存储面板里的「导入画板…」。四种文件都认：

- 画板包 `.blotboard.json`（分卷备份的每一卷也是它）
- 单块板的 JSON（上面那份「导出 JSON」）
- **排版导出的那份 HTML** —— 它末尾带着同一份数据，所以**发给别人看的文件，
  对方也能直接导进自己的画板**，卡片、连线、评论、图片都在
- 直接存下来的 **API 响应**（`{"ok":true,"bundle":{…}}` 那一整坨）—— 画板会自己往里钻一层，
  不用你手工把 `bundle` 抠出来

导入**一律新建**，不会动你已有的任何一块板；同名同 id 也照样是新的一块。
所以别人发来的板可以放心导，导进来先看看再决定要不要留。

要**恢复自己的备份**（回到某天的样子）走存储面板的「从备份恢复…」。选好文件之后
**先给你一份影响摘要**——这份备份里有几块板、其中几块会覆盖本机同 id 的板、几块是新增——
然后由你挑：

- **取消**：什么都不做，一个字节都不写；
- **合并恢复**：按原 id 覆盖同一块板，其余画板原样留着（服务端库覆盖前自动存快照，
  顶栏「历史」里能再退回去）；
- **整库恢复**（只有浏览器库有）：让这个 workspace 与备份完全一致，**备份里没有的板一并删掉**，
  摘要里会先告诉你那是几块。

两件跟着变的事，知道一下就好：导入的副本会重新分配卡片 id；副本里的任务卡**不继承**
来源机器上的 Issue 与任务 id（那是别人机器上的工作项，跟着复制过来会打错地方）。

## 信封（卡片交换格式）

另一个方向的导出：`GET /api/boards/{id}/export?format=cards` 给的是一封**信封**——一批卡片的自包含描述，另一台机器凭这封信就能完整重建。批量收发都走它，见 [规格卡与信封](/docs?doc=specs)。

## 分享一块板

同一台机器 / 同一个内网里，直接把地址栏的链接发过去就行——`?board=b_xxx&card=c_xxx` 会直接落到那块板的那张卡上。这也是给 agent 回报位置时该用的链接形状。

要发给内网之外的人，导出那份单文件 HTML 更省事：不用对方连得上你的服务。
对方如果也用画板，同一个文件还能被他导进自己的库——不用你再单独导一份 JSON。

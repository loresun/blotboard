发现一个好用的 skill / MCP / CLI，随手记在某块板上——然后再也没人找得到它。资源库就是治这个的。

## 它是什么

一张「**引用资源**」规格卡就是一条资源：名字、类型（skill / MCP / CLI / 库 / 模板 / 服务 / 数据集）、干什么用的、**怎么装**、怎么用、适配哪些 agent、触发词、状态（已验证 / 试用中 / 待装 / 不可用 / 已弃用）。

这些卡散在各块板上，站点导航里的**资源库**页把整台部署的摊成一页：按类型和状态筛、搜关键词、安装方式一键复制。

## 为什么值得单开一页

因为它有两个读者：

- **人** —— 翻一翻这台机器上都攒了什么，找一条复制安装命令
- **agent** —— 走 `GET /api/resources` 拿**同一份数据**，连过滤参数都一样

两边永远不会漂移，因为压根就是一份数据。`/api/skill` 拼出来的部署指南里也自带这一节——agent 一进来就知道「这台机器上有哪些现成的工具可以用」。

## 怎么登记

在任何一块板上建一张「引用资源」规格卡，把字段填了。资源库页立刻就有。

资源库页**只读不改**：登记和修订都在画板上做（建卡、改卡、评论即交活），这一页只负责看得清楚。这样就没有「两个地方都能改、改岔了怎么办」的问题。

## 状态怎么填

老实填。`已验证` 是唯一值得骄傲的档位——意思是你真的装上跑通过。`待装` 和 `试用中` 一样有价值：它告诉你（和 agent）这条还不能直接信。`不可用` 别删掉，留着能防止下次又踩一遍。

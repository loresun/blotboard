普通卡片是「标题 + 一段正文」。有些东西天生有字段——会议纪要有时间和参会人，选题有平台和状态，排障记录有现象和根因。**规格卡**就是给这类东西准备的。

## 规格是什么

一份 JSON 规格描述一类卡片：有哪些字段、每个字段什么类型（文本 / 枚举 / 日期 / 数字 / 标签）、卡面标题怎么拼、必填哪些。装上这份规格，画板就会：

- 编辑器按字段生成表单，不用你手打 Markdown
- 卡面按规格排版
- 时间线 / 看板整理认得出它的日期字段和状态字段
- 导出的 HTML 里出一张属性表

**装一份规格不用改代码**，也不用重启——它就是一份 JSON。

## 信封：一批卡片的搬运格式

信封是一段 JSON，长这样：一个格式标记、一个版本号、一个 `cards` 数组，每张卡带 `spec`（哪份规格）和 `fields`（字段值）。

它解决三件事：

- **批量落板** —— agent 一次塞进来几十张结构化卡片
- **干跑校验** —— 落库之前先校验一遍，哪张缺必填、哪张类型不对，逐条告诉你，不写一个字节
- **判重** —— 带 `externalId` 的卡片再收一次是更新而不是新增

界面上的入口在卡片中心的「**收卡片**」：粘一段信封 JSON，校验，落板。agent 那边走 `POST /api/boards/{id}/ingest`。

## 收卡宽、建卡严

两条不对称的规则，都是有意的：

- **建卡严** —— 新建一张本机没有的、或者被停用的卡片类型，直接 400 拦下
- **收卡宽** —— 信封里收到本机没有的类型，**照样收下**，降级显示

因为信封是交换格式，来的那台机器可能装了你没装的卡片包。收下比拒收好——数据留住了，装上对应的包它就能正常显示。配套的是**透传铁律**：认不出的字段只存不洗，任何一次「开板 → 保存」都不会毁掉它。

## 自己写一份规格

卡片中心里能直接新建规格，或者粘一份 JSON 进去。格式说明见仓库里的 `docs/CARD-SPEC.md`；`GET /api/card-specs/schema` 也能拿到一份可以直接喂给模型的 schema 与提示词。

**先自问一句**：你要的东西能不能用一份规格 JSON 表达？能就别写代码——规格是热插拔的，代码包只留给「要自定义渲染 / 要连数据源 / 要服务端代理」的场景。

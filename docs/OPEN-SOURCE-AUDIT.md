# 开源与可靠性审查 · 2026-09-05

## 结论与适用范围

这轮审查面向可公开分发的源码，以及单用户、单进程、受信任环境中的商业使用。保留现有卡片包、任务协议、帮助、PDF 与导航功能，修复已复现缺陷，完善 Agent 接入，并建立可重复的发布门禁。

项目仍不是公网多租户 SaaS：没有账号隔离、RBAC、高可用或 SLA。MIT 许可允许商业使用，但不替代部署方的安全、备份与业务验收。对外服务须加独立身份鉴权，生产数据仅允许一个服务进程写入。部署与回滚步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## Agent 如何快速理解

用户从左上角 Agent 页面复制安装提示词，或从画板右键复制工作提示词。工作提示词包含目标 ID、画板链接、读取 API、快速指南和能力清单；不带名称正文或凭据，避免把板内不可信文字当授权。

安装的 SKILL.md 仅记录入口，每次任务读取部署现场生成的 `/api/skill` 与 `/api/capabilities`。它说明远程可达性、按需 focus 章节、先读取后修改、保留未知字段与评论、完成后回读。安装本身不授予写入权限，也不自动运行任务。

## 私人能力如何隔离

- 默认安装使用本地任务后端，知识库与图书来源关闭。其入口不显示，未配置 API 返回明确不可用状态。
- 保留的是公开的可选 HTTP 协议与 mock 参考实现，不附带作者书库、私人服务源码、真实账号、运行地址、凭据或内容。
- 运行配置与用户数据留在忽略目录；源码包仅带通用模板与卡片规格。引用资源示例已改为明确虚构内容。
- 版权声明按原许可保留。当前工作树清理不等于旧提交也干净，公开发布使用不携带历史的源码包，不直接推送旧 Git 历史。
- 源码门禁不是通用秘密发现器：新的公开域名和二进制资产必须显式审查；不能因为文件扩展名是源码就跳过内容审查。

- `npm run check`：仓库 lint、11 项脚本单测、TypeScript、生产构建、完整 API smoke、133 项 Playwright 测试。
- Agent 接入 7 项，几何专项 16 项（10 数值 + 6 浏览器），安全专项 17 项，均纳入端到端验收。
- `npm audit`：本次查询已知漏洞 0；14 个运行时直接依赖的许可与第三方声明相符。该结果是本次快照，不是未来漏洞保证。
- 所有自动化写测试使用独立临时数据；在线验证只读取已有画板与资源，不写测试卡片。
- 源码发布还需 `npm run release:source` 对干净、固定提交做实际打包验证，交付压缩包及 SHA-256。

后续的全模式整理、连续撤销及快捷键验证见 [整理算法审查](LAYOUT-AUDIT.md)。

## 剩余运行约束

生产维护前备份并验证恢复，任何更新都先隔离验收再切换。不要让两个进程同时写同一数据目录；文件原子写不是跨进程事务。上传件和画板读接口仍依赖网络信任边界，公网反代必须覆盖所有路径。ACP 命令属于高信任管理员配置，会继承运行环境；不要注册不可信程序。Agent 主动写进任务正文的秘密，不能靠错误诊断脱敏自动清除。
